## Tech Leader Verdict

### Architecture Assessment

The implementation demonstrates strong architectural discipline in the core engine layer — the three swap boundaries (StorageBackend, AdventureModule, NarratorBackend) are preserved, the multi-tenant `campaign_id` injection via `ScopedMCPToolset` (a real `WrapperToolset` dataclass subclass) correctly survives pydantic-ai's `for_run`/`visit_and_replace` rebuild, and the ADR-029 narrator-as-tool-use-agent pattern eliminates the `effects[]` complexity cleanly. SOLID principles are well-applied: the `NarratorBackend` protocol (Dependency Inversion), `storage_factory` seam (Open/Closed), and single-responsibility `ScopedMCPToolset` wrapper all hold.

However, the **session-lease enforcement layer has a fundamental architectural gap**. The D1 route redesign (`/campaigns/{id}/**` → `/me/game/**`) was done correctly at the route level (T112-T116, `_get_active_campaign` helper), but the `LeaseGuardMiddleware` was not adapted to the new route scheme. The middleware's `_CAMPAIGN_ID_RE` regex (`^/campaigns/([^/]+)`) matches a route pattern that no longer exists, while `_EXEMPT_SUFFIX_PATTERNS = [^/me.*$]` exempts every D1 route. The result: **the lease subsystem is architecturally present but functionally inert in production**. The `LeaseService` is fully implemented and tested, but nothing on the write path calls `validate()`. This is not a missing feature — it's a broken wire between two correctly-built components.

The `turn_duration` metric placement (`play.py:387-389`, outside the `turn_span` block at L310) is a minor but telling robustness gap: the histogram misses exactly the failure cases (narrator raises → 422) where latency measurement matters most.

Complexity is well-managed overall — the codebase is readable, well-commented, and the ADR-to-code traceability is strong. The `force_takeover` parameter on `acquire()` is an unnecessary complexity that creates a dangerous public API surface for no current consumer.

### ADR Compliance
- ✅ **ADR-022 (OIDC JWT/JWKS validation)**: Compliant — fail-closed boot, `kid` required, `exp` mandatory, `iss` always verified, graceful degradation with JWKS cache + validated-token cache. **Deviation**: cache key uses full SHA-256 (`oidc_auth.py:87`) not `sha256(token)[:16]+exp` as ADR-022:42 and CONTRACTS.md:668 specify. The deviation is stronger (more collision-resistant) but creates doc/code drift. **New ADR needed**: amend ADR-022 or CONTRACTS.md to document the full-hash decision, and document the 300s revocation gap in a threat model.
- ⚠️ **ADR-023 (Session lease acquire/takeover)**: **Partial violation** — ADR-023:55 states "LeaseGuardMiddleware intercepts all mutating HTTP requests... calls LeaseService.validate() before passing to the route." The spec (spec.md:469) reiterates "LeaseGuardMiddleware is retained; it validates X-Session-Lease on mutating requests." The implementation exempts all `/me/**` routes (`lease_guard.py:38`), making the middleware a no-op on every D1 route. The `takeover` validates `current_token` (FR-027 ✓) and expiry uses `<=` (FR-028 ✓), but the enforcement wire is broken. **New ADR needed**: ADR-023 must be amended (or a new ADR created) to document the D1 enforcement gap and the route-level `require_lease` dependency as the remediation path.
- ✅ **ADR-024 (OTel no-PII)**: Compliant — `span_set_error` records only `type(exc).__name__`, generic handler logs type only, `turn_span`/`narrator_span` wired with campaign_id/account_id only. Minor: `turn_duration` placement outside `turn_span` block.
- ✅ **ADR-025 (DB-backed campaign registry)**: Compliant — `AccountRepository` used in play routes, `account_id` set on campaign rows.
- ✅ **ADR-026 (Postgres TLS)**: Compliant — TLS by default, non-production override.

### Cross-Report Synthesis

**Convergence on lease enforcement (CRITICAL)**: Both reports independently identified the same root cause — `LeaseGuardMiddleware` exempts all `/me/**` routes, making the lease subsystem non-functional on the write path. The QA report flagged it as "design inconsistency" and "deferred"; the Security report escalated it to CRITICAL (C-01). The convergence is significant: this is not a niche edge case but a systemic architectural disconnect visible from both QA and Security perspectives.

**Convergence on dead code (LOW)**: Both reports independently flagged `lease_guard.py:104-105` as unreachable duplicate of the check at L95-96. This is a minor symptom of the same root cause — the middleware was written for `/campaigns/{id}/**`, adapted for D1 with an exemption blanket, and the old code path was left as dead code rather than removed. The dead code is a **tell**: it signals the middleware was not refactored for D1 but rather patched with an exemption, leaving the original logic orphaned.

**Pattern: spec-implementation disconnect on D1 migration**: The D1 route redesign (Phase 2a) was executed correctly at the route level but left two orphans: (1) the middleware enforcement wire was cut and patched with an exemption comment, and (2) CONTRACTS.md §13 still documents `/campaigns/{id}/session` routes. Both are symptoms of a D1 migration that touched routes but not the cross-cutting middleware and contracts.

**Pattern: prevention implemented, detection skipped**: T006b specified a belt-and-suspenders approach (prevention wrapper + detection audit). Only the prevention was implemented. This mirrors a broader pattern where the "harder to test" defensive layer is dropped — the `scoped.filtered()` composition test, the allowlist-block test, and the LRU eviction test are all absent for the same reason: the prevention "looks correct" so the detection/test layer is deprioritized.

**Pattern: security-critical public API surface**: `force_takeover=True` on `acquire()` and the unbound lease token (no `account_id` check in `validate`/`release`) both represent security decisions deferred to "callers will do the right thing." The `force_takeover` parameter is unreachable via HTTP today but is a loaded gun on a public singleton method.

**Distinguishing "spec deferred" from "implementation silently skipped"**:
- **Spec deferred (legitimate)**: Session-lease endpoints themselves (FR-007, spec.md:1053, Q&A at :1440), `python-jose` → PyJWT migration (spec.md:1458), sessionStorage → httpOnly cookies (spec.md:1431). These are documented deferrals with clear rationale.
- **Implementation silently skipped (not legitimate)**: (1) Lease enforcement on D1 routes — spec says "retained and validates," implementation says "deferred" in a code comment only. (2) T006b detection audit — task marked [X] but detection absent. (3) CONTRACTS.md drift — spec says "updated" (T007) but §13 still has old routes. These are gaps between what the spec/ADR requires and what was delivered.

The implementation is architecturally sound in the core engine and narrator layers, with strong ADR compliance on the majority of decisions.
