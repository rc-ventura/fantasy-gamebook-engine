### Medium & Low Findings
| Severity | OWASP | Description | Location |
|----------|-------|-------------|----------|
| MEDIUM | A04 | **TOCTOU race in `validate()`**: `validate()` uses a non-locking `SELECT` (no `FOR UPDATE`) and runs in its own transaction that commits *before* the protected route mutation executes. Between `validate` passing and the route's state change, a concurrent `takeover` can rotate the holder. The original mutation then proceeds under an invalidated lease. `acquire`/`renew`/`release`/`takeover` all use `FOR UPDATE` — `validate` is the outlier. | `sessions/lease.py:205-211` |
| MEDIUM | A04 | **`renew()` failure swallowed**: `require_lease` catches *all* exceptions from `renew()` and ignores them. If the lease was taken over between `validate` and `renew`, `renew` raises `409` — which is swallowed — and the route mutation still completes under a lease the caller no longer holds. The `except Exception: pass` defeats the lease check. | `sessions/lease.py:536-539` |
| LOW | A01 | **Lease enforcement is opt-in**: `require_lease` returns as a no-op when no lease row exists for the campaign. The SPA defaults to `VITE_SESSION_LEASE=false`, so in the default deployment all mutating routes are unguarded. Documented as intentional, but the "single active session" guarantee only applies when the client opts in. | `sessions/lease.py:507-509` |
| LOW | A02 | **Non-constant-time `account_id` compare short-circuits token compare**: `db_holder != account_id` uses Python's `str.__eq__` (not constant-time) and short-circuits the `or` before `_tokens_match` runs. Creates a timing oracle on whether the supplied account is the current holder. Not practically exploitable in production (account_id comes from validated JWT, attacker can't vary it per-request), but violates the constant-time principle. | `sessions/lease.py:231, 319` |
| LOW | A05 | **`ENV` case-sensitivity inconsistency**: `_is_production` in `app.py` uses case-sensitive `== "production"` (line 161) while the OTLP guard in `setup.py` uses `.lower() == "production"` (line 81). If `ENV=Production`, the OTLP insecure-mode guard fires but `/docs` and `/redoc` remain enabled (docs-disable check fails). | `api/app.py:161` vs `observability/setup.py:81` |

## Tech Leader Verdict

### Architecture Assessment

The implementation demonstrates strong architectural discipline. The three swap boundaries (Storage, Adventure Module, Harness) are preserved — `play.py` routes depend on `NarratorBackend` and `CampaignRegistry` interfaces, not concretes. The ADR-029 refactor (narrator as tool-use agent, eliminating `effects[]`) is a significant simplification that restores Phase-1 parity and enforces Principle I (Numbers Never in Prose) **by design** rather than by heuristic validator — this is the correct architectural direction.

The D1 route redesign (`/me/game/**` resolving `campaign_id` from the account, not the URL) is well-reasoned. ADR-031 correctly identifies that ASGI middleware cannot safely resolve `campaign_id` without bypassing FastAPI's `dependency_overrides`, and the route-level `require_lease` dependency is the right fix — it flows through the normal DI graph, respecting auth overrides in both test and production.

**SOLID adherence is strong**: Single Responsibility per module, Open/Closed via interfaces (NarratorBackend, StorageBackend, CampaignRegistry), Liskov substitution (FakeNarrator/PydanticNarrator interchangeable), Interface Segregation (narrator toolset filtered to `_NARRATOR_ALLOWED_TOOLS`), and Dependency Inversion (routes depend on `get_current_account`/`get_campaign_registry` abstractions, not concretes).

**Complexity is well-managed**: the `ScopedMCPToolset` wrapper (learning-lesson applied) removes the LLM from the security-critical `campaign_id` path — prevention over detection. The `_assert_narrator_campaign` post-audit is correctly framed as belt-and-suspenders detection.

**Scalability gap**: `CampaignRegistry` remains in-memory (ADR-025 durable replacement tracked as T037, deferred to slice 004). This blocks horizontal scale (two replicas = two divergent registries) but is explicitly documented and tracked — not a silent drift.

### Cross-Report Synthesis

**Pattern 1 — Skipped tests masking broken contracts (systemic risk):**
The HIGH bug (broken `test_postgres_leases.py`) is the same root pattern as the learning lesson "contract drift requires live integration test." Both reports independently confirm it. The tests are skipped without `DATABASE_URL` and would `TypeError` if run. This means the H-02 fix (account_id binding) has **zero executed test coverage** — the only tests that exercise it are the broken, skipped ones. This is not an isolated bug; it's a process gap: signature changes were not propagated to test call sites, and CI doesn't run live-DB tests, so the drift is invisible.

**Pattern 2 — Incomplete propagation of fixes across components (systemic):**
The pool-limits fix (L-POOL) was applied to `LeaseService` (`lease.py:98-104`) but **not** to `AccountRepository` (`accounts.py:62`), which connects to the same Postgres. The M-02 control-character stripping was claimed in a comment but not implemented. Both are cases where a fix was applied in one location but not propagated to parallel locations. This suggests a need for a "fix propagation checklist" when a remediation touches multiple components sharing a pattern.

**Pattern 3 — TOCTOU in check-then-act lease enforcement (design-level, isolated to `validate`):**
Both reports converge on the same finding: `validate()` uses a non-locking `SELECT` while every other lease operation uses `FOR UPDATE`. Combined with the swallowed `renew()` failure in `require_lease` (`except Exception: pass`), a mutation can proceed under a taken-over lease. Security rates this MEDIUM (narrow concurrency window); QA rates the `renew` swallow as a contract violation ("metrics must not break a turn" but lease renewal failure is silently swallowed). This is a design-level issue, not a crypto or access-control bug — all 7 cycle-1 critical/high fixes are verified correct by both reports.

**Pattern 4 — Defense-in-depth correctly layered:**
The `ScopedMCPToolset` (prevention) + `_assert_narrator_campaign` (detection) pattern is correctly implemented and documented. The LOW finding about `_assert_narrator_campaign` raising `RuntimeError` on LLM hallucination (false positive when prevention is active) is a robustness concern, not a security one — the engine is safe, but the audit breaks the turn unnecessarily.

**Pattern 5 — ENV case-sensitivity inconsistency (low-risk but trivially fixable):**
`app.py:161` uses `== "production"` (case-sensitive); `setup.py:81` uses `.lower() == "production"` (case-insensitive). If `ENV=Production`, the OTLP guard fires but docs remain enabled. Trivial fix, no security impact in practice.

**Architecture verdict**: The architecture is sound, ADR-compliant, and the cycle-1 critical/high fixes are all correctly implemented and verified by both reports. The remaining issues are: one HIGH test bug (blocking), two MEDIUM implementation gaps (pool limits, control-char stripping), and several LOW design-level refinements. None are fundamental — they are targeted, fixable issues.
