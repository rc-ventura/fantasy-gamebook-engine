## Tech Leader Verdict

Verified all flagged findings against the actual code before weighing the reports. Both
MEDIUMs are accurate: CSP extends `connect-src` but has no `frame-src`, so
`automaticSilentRenew: true` (`oidcConfig.ts:37`) fires an iframe to Dex that CSP blocks
— enabled-but-dead config; and `DashboardPage.tsx:88` swallows a 401 (`.catch(() =>
null)`) while `useGame.ts` redirects via `redirectToAuth()`. tasks.md's "four bugs found
live" claim is real; `main.tsx`'s tokenBridge import-order race is empirically-fine-but-
not-contractually-guaranteed.

### Architecture Assessment
Clean slice that does exactly what ADR-034 promised. The auth seam (ADR-011 /
`client.ts`'s `setTokenProvider()`) held under a real swap: paste-a-token stub → full
OIDC+PKCE touched only `useAuth.ts`, `AuthPage.tsx`, `main.tsx`, `oidcConfig.ts`,
`tokenBridge.ts`, and a new `/callback` route — zero backend changes, `oidc_auth.py`
(ADR-022) reused as-is. Public-client PKCE makes FR-002 (no secret in browser) true by
construction; replay/`code_verifier` handling delegated to a maintained library, not
hand-rolled. One soft spot: CSP is now managed in two places (static `index.html` meta +
build-time `vite.config.ts` replace) and only `connect-src` was reasoned about — the
`frame-src` renewal path fell through the gap. Complexity proportionate; no
over-engineering.

### ADR Compliance
- ✅ **ADR-034** (SPA-direct PKCE public client): Compliant — public client, id_token bearer, local-only sign-out, sessionStorage, local-Dex metadata-seeding all as specified. Minor: the ADR frames `automaticSilentRenew` as a Story-2 enabler, but the shipped CSP renders it inert.
- ✅ **ADR-011** (auth seam): Compliant — seam absorbed the real-OIDC swap with no bleed into the rest of the SPA, exactly its intent.
- ✅ **ADR-022** (OIDC JWT/JWKS validation, fail-closed): Compliant — backend untouched; sending the `id_token` keeps it provider-agnostic.
- 📝 **New ADR needed**: None. The `frame-src`/silent-renew inconsistency is an implementation bug, not a decision. If the team elects to drop `automaticSilentRenew` rather than fix CSP, record a one-paragraph ADR-034 amendment instead.

### Learning Lessons Applied
- ✅ Applied in spirit: this slice live-tested the real Dex+backend stack and surfaced 4 bugs static analysis missed.
- ✅ QA ran `tsc -b --noEmit` directly, not the RTK-proxied path (per the existing `rtk_proxy_masks_tsc_errors` lesson).
- 📝 **New Learning Lesson recommended**: *"Auth/redirect/token-lifecycle flows must be exercised live — mocked-provider unit tests and static analysis pass while the real redirect, silent-renew, and expiry paths are broken."* Every material gap this cycle (silent-renew CSP-blocked, dashboard-expiry dead-end, discovery-failure swallow, bare-`/callback` spinner) is a runtime-only, timing-or-CSP-dependent failure invisible to CI. Distinct from the existing contract-drift lesson (field-shape divergence) — this is browser auth state machine + CSP + IdP timing.

### Cross-Report Synthesis
Two systemic root causes underlie the scattered findings, not five isolated nits:
1. **"Gate at the boundary, not at the primitives."** Both reports independently flagged the DEV-token fallback lacking an `import.meta.env.DEV` gate on the *inner* functions (`client.ts:42-47`, `useAuth.ts:60-66`), though the outer layers are gated and proven dead-code-eliminated. Not exploitable without XSS — one root cause, two files.
2. **"Happy-path CSP, unexercised renewal/expiry CSP."** QA's missing-`frame-src` and Security's CSP-via-`<meta>`/silent-no-op both trace to CSP being updated only for the login token-fetch (`connect-src`) while renewal/expiry paths were never runtime-exercised — the same thread as the dashboard-expiry dead-end. MVP paths (US1/US3) are live-verified and solid; all debt clusters in **session longevity** (FR-004 works via rehydration; FR-005 is where it sits).
